## 引号方向的只读验证

仅运行固定 ASCII/Base64 常量，解码后打印哨兵和 Python 版本；没有写启动器或执行 payload。

- 与官方 `raw_arg` 等价的原始 cmd 命令行：退出 0、哨兵存在、Python 3.9.25、stderr 空。
- `pwsh -NoProfile -NonInteractive -Command`：同样通过。
- 显式 `C:/Program Files/Git/bin/bash.exe -lc`：同样通过；这是 Windows Git Bash，不是 native POSIX。
- 尚未测试完整生成的 bootstrap、中文/空格布局、真实宿主或 Linux。

探针错误均定位在工具边界：最初 UTF-8 text capture 无法解码 WSL 的 UTF-16 输出；改为 bytes capture 后看到真实错误。Python 的 argv-list 转义不等于 Codex 的 cmd `raw_arg`，会把 `-c` 的引号错误地传给 Python；改用源码对应的原始 Windows 命令行后成功。Windows 子进程查找裸 `bash` 命中了 System32 的 WSL 启动器，而不是当前 harness 的 Git Bash；其磁盘挂载失败与 Trellis 无关。改用已存在、明确定位的 Git Bash 检查引号，未修复 WSL、安装 Linux、清除环境或增加重试。

## 本仓库接口与迁移

- 模板 `packages/cli/src/templates/codex/hooks.json` 仅注册 UserPromptSubmit 与 SubagentStart，不新增 SessionStart。
- `getHooksConfig` → `collectCodexTemplates` → init/update 同一模板链。
- 当前 `.codex/hooks.json` 逐字节等于旧模板的 `{{PYTHON_CMD}}=python3` 渲染；与 Windows `python` 渲染不同。不是原始占位符文件的字节 twin。设计审批需明确允许按已确认的旧渲染基线同步该镜像，不借此覆盖其它已有差异。
- `collectTemplateFiles` 目前只对 Codex agent model keys 做保留；`analyzeChanges` 是全文件 hash 分类，没有 Codex hook 条目级迁移。不能只替换整个 hooks.json 后宣称保留用户条目。
- 通用迁移类型仅 rename / rename-dir / delete / safe-file-delete；不为本任务扩展通用迁移框架。
- `uninstall-scrubbers` 通过已有 manifest 脚本路径识别归属。新命令保留清晰的 `.codex/hooks/<script>.py` 参数，必须用真实卸载测试证明仍能剥离自有 hook 而保留用户 hook。
